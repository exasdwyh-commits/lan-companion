# 澜的潮汐居：场景规划

> **2026-11-01 决策更新**：用户明确要求完整复用 [moli-room](https://github.com/norsizu/moli-room)，保留其娱乐模式。当前底座已改为 `MALFOY-ENGINE/web/moli-room/`；本页后续作为主题改造参考，不再按旧分期重新开发家具、日程或小游戏。交付与后续顺序见 [WORLD-MOLI-05](updates/2026-11-01-WORLD-MOLI-05-reuse.md)。

日期：2026-10-31。状态：设计提案，依据用户已认可的 Three.js 小世界方向；具体布局、场景命名及行为为本轮推荐，尚未逐项确认或实现。

## 1. 推荐范围

先完成一间精致、可以观察她生活的海边小屋，随后扩展相连的小露台，最后考虑岸边探索。小屋承担日常陪伴，露台承担轻松玩耍；海面先作为远景，控制资产和动作成本。既有真人视频世界继续承担本体表现，这套场景用于 Q 版神识，不改变同一角色的身份。

渲染路线建议：三维环境配 Q 版角色，固定主视角加有限旋转。当前二维角色先验证行为流程；可动 3D 模型验收后替换，保持地点、动作和互动入口一致。Hyper3D 现有预览没有可用导出和合格动作，不能作为模型已完成的前提。

## 2. 空间布局

采用剖面小屋，打开朝向镜头的两面墙；以现有约 8×6 的地面为尺度草案。中央留出连续通道，鲸尾与头发也要计入角色通行宽度。

```text
                  海面远景 / 云 / 月光
┌───────────┬─────────────────┬────────────┐
│ 书架＋书桌 │     大窗＋窗台     │ 软床＋床头灯 │
│   阅读角   │     发呆看海       │   休息角     │
├───────────┴─────────────────┴────────────┤
│              连续通道                      │
│ 盆栽           圆地毯 / 玩耍区               │
│                与用户互动        通往露台 → │
└────────────── 朝镜头开放 ──────────────────┘
```

家具各有可站立的接近点和动作位置，例如走到床边与坐到床上是两个阶段；不能靠坐标瞬移或图片压扁代替动作。桌、床、窗沿的碰撞与可点击区域分别定义。第一期不在通道添加茶几或装饰障碍。

## 3. 三个场景的职责

| 场景 | 用途与画面重点 | 自主行为 | 用户互动 | 优先级 |
|---|---|---|---|---|
| 潮汐小屋 | 温暖、安定、长期陪伴；书桌、地毯、窗、床 | 看海、翻书、伸懒腰、玩小球、休息 | 邀请过来、选地点、摸头、一起看海 | 首期，只做此处 |
| 贝壳露台 | 同一小屋的室外延伸；木台、栏杆、少量盆栽 | 追光点、看飞鸟、摆弄小物件 | 抛小球、邀请舞蹈、切换观景 | 小屋动作达标后 |
| 星潮浅湾 | 低频出游；浅水、发光贝壳、短栈道 | 沿岸散步、观察潮水 | 一起探索一条短路线 | 远期提案 |

露台采用预定义出口与转场；浅湾再扩展独立场景。第一期不承诺跨地图自由游泳或开放世界。

## 4. 美术与镜头

- 风格：精致的微缩海边居所。主体为奶油白、浅木色、雾蓝，金色只用于暖灯和小装饰；保留 B 版深蓝头发、鳍耳、鲸尾的识别度。
- 家具：圆角木桌、布艺床垫、柔软地毯、陶瓷杯；通过轮廓、粗糙度和接触阴影区分材质。优先替换窗、桌、床三件大资产，再加小物。
- 层次：角色和中央活动区最清楚；后侧家具次之；海面远景低对比、慢运动，避免抢走角色注意力。
- 镜头：默认前方略俯视，能看清脸和脚；提供全屋与角色近景两个预设，手动调整后由用户决定恢复。缩放不能让角色或家具遮住全部画面。
- 昼夜：日间浅蓝海面与窗光、傍晚暖光、夜间月色与桌灯；先做日夜两套，再考虑平滑过渡。雨天排在角色动作之后。
- 界面：画面占主体，控制项精简为自主活动、昼夜、视角；物件悬停出现短提示，点击再反馈。聊天沿用产品入口，后续集成时避免重复播音。

## 5. 她如何自己玩

每个活动按“选地点 → 寻路 → 对齐 → 做动作 → 停留 → 结束”执行。走到书桌旁只能叫“来到书桌”，拿起并翻书才叫阅读动作。首期行为选择使用轻量规则，不依赖大模型逐帧控制。

| 活动 | 可见表现 | 所需资产 | 中断方式 |
|---|---|---|---|
| 看海 | 走到窗边、转向、轻摆鲸尾 | 行走/转身/待机 | 直接回应用户 |
| 读书 | 就位、持书、偶尔翻页 | 坐下/起身/持书、书道具 | 放下书再起身 |
| 玩球 | 靠近球、轻碰、追一小段 | 短移动/触碰、小球 | 球停稳，返回待机 |
| 休息 | 到床边、坐下、短暂停留 | 上下床或坐卧过渡 | 起身后移动 |
| 舞蹈 | 在地毯内完成短循环 | 合格的舞蹈动作 | 平滑回到待机 |

选择应避免连续重复活动，依据时段和当前状态加权；刚被用户邀请时暂缓自主换地点。用户指令优先，正在聊天、朗读或唱歌时保留相应活动位置。后台页面暂停模拟，恢复时不编造离线发生的共同经历；首期不写入真实记忆。

最低可交付动作先做待机、走路、转身、坐下与起身。读书/玩球随后，完整舞蹈和躺卧最后；每项有缺资产的降级状态，不能用气泡冒充动作。

## 6. 制作顺序与验收

| 阶段 | 交付 | 完成条件 |
|---|---|---|
| A 空间定稿 | 一间小屋布局、主镜头、窗桌床的材质和灯光 | 主视角看清角色；所有物件入口明确；家具不挡通道 |
| B 角色可用 | 同身份可动角色、待机/走路/转身 | 侧背面身份一致；手脚、裙摆和鲸尾不明显粘连、拉扯；真实导出并加载 |
| C 生活闭环 | 至少三种有不同视觉表现的活动 | 连续观察十分钟可见多种活动；无穿模卡住；点击可改变活动；暂停和恢复有效 |
| D 产品接入 | 场景入口、原有聊天/声音/状态衔接 | 以隔离数据验证；切换不重置会话、不叠播；确认活动与真实服务状态一致 |
| E 扩展 | 露台、短路线、玩具 | 小屋已达标再制作，不并行堆地图 |

验收另含：小窗口与窄屏、旋转极限、家具和新装饰的碰撞、目标不可达、快速连续点击、资源加载失败、后台恢复。性能先记录实际设备的帧时间和资源开销，再确定画质档位；不能以静态检查或截图代替运行与动作验收。
