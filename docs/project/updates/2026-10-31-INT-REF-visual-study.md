## 主要发现

1. dsh-pet 本地 `dsh-pet/assets/webm/` 有 109 个 WebM；配置把待机、转向、拖拽、点击、移动、分类动作、业务事件、睡眠分池，权重挑选，同一事件档可有多候选。文件名包括吃东西、吹笛、玩水枪、工作思考、点击害羞、走路及睡眠三段。实际动作质量与风格仍需逐段观看；文件计数不等于 109 种完整交互。
2. 其播放器 `src/client/pet/animation/animation.ts` 双 video 槽、后台就绪交接、代次丢弃旧加载、错误回执、释放 blob，解决加载和中断时的空白/旧结果问题。双缓冲本身不等于已验证交叉淡化。澜图集是全身不同姿态，直接叠透明图可能双脸双手，应实测再定转场。
3. `src/client/pet/card/sleep-machine.ts` 将同一套入睡、睡眠循环、醒来绑定；入睡被打断不强行播放起身。`FEATURES.md` 描述睡眠时暂停多数主动行为和提醒。素材设计与状态机必须成套，缺过渡不能伪称自然过渡。
4. 工作进行中循环，完成/失败一次性；气泡说明可与实际工具事件对应，见 `FEATURES.md` 与 `src/shared/work-status.ts`。实际业务事件不存在时不编造“正在读文件”。
5. AIRI 的 `packages/stage-ui-live2d/src/controls/manifest.ts` 从模型读取表情/动作，`controls/policy.ts` 控制启用，`composables/live2d/eye-tracking.ts` 按画布和模型坐标换算追视，motion-control 管理控制权。它需要具备动作与参数的 Live2D 模型；引入代码不能自动生成澜的分层原画与绑定。
6. 当前澜 `chibi-performance.js` 有 16 个情境姿态、工作/阅读/唱歌少量变体、独立走路/舞蹈图集和情境优先级；许多是静态或两姿态切换。`CHIBI-04/05` 已记录用户不满意旧舞蹈，B 方向是概念，不能称完成的模型/连续舞蹈。两项项目文档对素材现状有先后快照，开发时须核对现有文件。

## 推荐制作顺序（建议，非已批准新视觉方向）

- **P0 身份和动作样片**：沿用用户已选 B 的蓝发、鳍耳、鲸尾；先制作同画布、同地面线和锚点的待机循环、点击回应、走路、工作各一段，检查 180px 可读性、身份、连续性、透明边缘与首尾帧。真人世界与神识共享身份，不搬别人的角色。成本集中于原创素材及视觉验收，收益最大。
- **P1 播放与导演**：沿用当前舞台；设计动作清单和显式触发/优先级/循环/中断/恢复，旧画面维持到新资源就绪；针对差异大的轮廓测试硬切、短淡出或过渡帧，避免默认双图交叉重影。屏幕边界、拖拽反馈与减少动态保持。
- **P1 业务接入**：DW-06 真实事件驱动工作、等待、成功、失败；阅读/唱歌业务由现有负责人协调。缺少素材时有明确降级，不伪装为完整动画。
- **P2 扩展素材库**：先补同套入睡/循环/起身，再补阅读、唱歌、生活小动作、节日或剧情动作；建立来源、许可、场景、时长、锚点、循环、转场和可用状态清单。按真实使用频率增加，避免先堆素材数量。
- **后续 Live2D**：先取得合格的 B 方向可编辑分层 PSD、绑模与动作；借鉴 AIRI 的动作清单、参数控制和模型探针，不迁入整套 monorepo。
