### 1. 新增四个可复用的量测脚本

| 脚本 | 量什么 | 为什么要单独写 |
|---|---|---|
| `e2e-voice-check.js` | 一段 webm → STT → 流式 LLM → 切句 → 逐句合成 → 排播时间轴 | 首音由四段串行相加决定，只有真打一次才算得出来。跳过麦克风，等价于 `voice-capture` 交出音频的那一刻 |
| `voice-latency-probe.js` | TTS 的固定开销与每字斜率、STT 的重复性 | 切句器的系数是拿这两个数解的，系数变了要能重新解 |
| `voice-timeline-sim.js` | 长回复的切句 → 合成 → 排播，不依赖模型 | 切句系数错了不报错，只在第三四块凭空空一段，只有排出时间轴才看得见 |
| `stt-compare.js` | 两个 STT 端口的速度 + 字错率（含加噪） | 换小模型能省一半时间，但掉准确率会直接改变她回什么，必须一起量 |

### 2. `stt_server.py` 两处修复（P0）

都是「现在没坏、重启就坏」的类型：

**(a) 启动必须联网。** `WhisperModel("small")` 传的是模型名，faster-whisper 会先调 `huggingface_hub` 查 revision。本机 HF 不通（SSL EOF），缓存明明在 `~/.smartcompanion/models/faster-whisper-small`，服务却起不来。改用 `resolve_model()`：本地目录存在就传绝对路径。实测启动 `0.3s`（原来卡在联网重试）。

**(b) 解码依赖 PyAV，重启即 500。** faster-whisper 1.2.1 调 `av.open(path, metadata_errors="ignore")`，而 venv 里是 PyAV 19.0.2，已移除该参数 → `TypeError: open() got an unexpected keyword argument 'metadata_errors'`。当前 8090 之所以正常，是因为那个进程 10-30 就启动了、内存里还是旧 av；**任何一次重启都会让语音输入整体失效**。改为先用 ffmpeg 解成 16k float32 再喂 `transcribe()`，ffmpeg 找不到时回退原路径。

改完后 8090 已用新代码重启，`/health` 返回的是本地绝对路径（即新代码生效的判据）。

### 口径修正（避免把口径差当成退化）

VOICE-03 记的「首音 2.96s」是**「STT 完成 → 听见第一声」**（首字 + 首块合成）；本次 4.60s 是**「用户说完 → 听见第一声」**，多算了 STT 那 0.9s。两者不是同一把尺，不能直接比。按同口径换算，本次「STT 完成 → 首音」为 3.7s，比 2.96s 慢，原因是 TTS 系数从 0.47 涨到 0.75（机器有其他负载）。
