## 完成内容

用户判定「优先解决实时聊天对话能力」，本轮把该判断落成可执行的链路设计，并先量了三个会决定方案形状的服务指标。

**改了什么、为什么：**

- `VOICE-PLAN.md` 追加「实时语音对话改造（VOICE-PLAN-02）」整节，明确它是上一节的**深化而非第二份方案**。上一节回答「分哪三条路径」（固定互动 / 本地控制 / 开放闲聊），本节只解决第三条：实时那条具体怎么改。
- 核心结论：首音 10.3s 不是算力不足，是**四段串行空等**——固定 4 秒录音窗口（`main.js:78`）、整段非流式 LLM（`main.js:585`）、整段阻塞 TTS（`main.js:413`）。因此任何单段提速都救不了，必须让它们重叠。
- 据实测把延迟预算写明为 **2.7–3.6s**（V1 目标），而不是喊「2 秒」。分项：端点 0.4–0.6 + STT 0.8 + LLM 首句 0.7–1.2 + TTS 首句 0.8–1.2。

**三个实测硬约束（这是本轮最有价值的部分）：**

1. **STT 耗时与音频长度无关**：1.5s / 3s / 8s 音频分别 0.86 / 0.81 / 0.86 秒 → 固定开销主导，**STT 不是瓶颈，不该优化它**。
2. **STT 不能并发**：单请求 0.82s，两请求并发变 1.43 / 1.62s（排队）→ **放弃「边听边增量转写」**，服务不支持，收益也不值得改造服务。
3. **TTS 无流式接口**：仅 `POST /tts` 返完整 wav，模块级 `_SYNTH_LOCK` 串行 → 只能靠「首句切短」+「播第一句时合成第二句」，不能指望流式音频。

**复用了哪些已有实现：**

- 切句直接复用 `lib/narration.js:splitSentences`，不另写一套；
- 分段合成范式沿用 `lib/voice-script.js`；
- 打断复用现成的 `cancelChat()` + `AUDIO_EPOCH` 作废机制（`main.js:688-692`），V2 主要工作量在假触发抑制，不在机制本身；
- 口型驱动复用 `world.html:475-484` 的输出侧 analyser。

**本轮额外落地：端点判定逻辑层**

设计文档说「尾静音 450ms 判定说完」，但这段逻辑是整个 VOICE-02 里最容易写错、又最难靠人工试出来的部分（300ms 起录保持、450ms 收尾、滞回阈值、噪声底跟随、超时兜底、句中换气不切断）。它不该等到接了麦克风才第一次被验证，所以先做成**纯逻辑模块**：

- 新增 `MALFOY-ENGINE/lib/voice-endpoint.js`：只吃逐帧 RMS，吐 `speech-start` / `utterance` / `discard` 事件。无浏览器 API、无 I/O、无依赖。
- 新增 `MALFOY-ENGINE/test/voice-endpoint.test.js`：10 项单测，用合成电平序列覆盖全部边界。
- **尚未接线**：采集层（`getUserMedia` + AudioWorklet）还没写，App 里没有任何路径会走到这个模块。它现在是「逻辑已验证、功能未存在」，不构成 VOICE-02 完成。

写测试时抓到一个真缺陷，值得记下来：初版把噪声底跟随的门槛写成 `holdThreshold`（1.7×底噪），结果环境音缓慢升高时门槛跟着抬高、跟随即刻停止，噪声底**锁死在低位**，风扇一吹就会误触发。改为按 `startThreshold`（2.6×底噪）判断跟随，并给上升加了约 1 秒时间常数，才能跟上 4 秒内的渐变。这类问题靠肉眼看代码发现不了，靠真实麦克风试也很难复现——正是纯逻辑 + 合成序列该抓的东西。

另外明确了本模块**已知不覆盖**的情况：突发的强噪声（关门、拍桌子、键盘猛敲）会被当成开口，因为噪声底按「缓慢漂移」建模，不是按「突变」建模。要治它得加突变检测或换 Silero VAD，V1 先不做。

## 剩余工作与交接

**当前限制或失败：**

- 延迟预算是**推算**，不是端到端实测；TTS 首句耗时（8–15 字）没有独立测量过，是「整段 2s 按比例缩短」的估计。领取 VOICE-03 时应实测短句耗时再校准。
- 端点检测选 RMS 而非 Silero VAD 是**基于包体敏感的取舍**，未做误触发率对比实验。持续背景噪音（风扇/空调）下阈值会漂，这一点已知且有备选方案。
- V2 打断的可行性**尚未验证**：Chromium 的 AEC 参考信号来自 WebRTC 音频通道，`<audio>` 元素播放的 TTS 不一定被纳入参考。这条没测之前不应动手写打断逻辑，否则会在「她听到自己」的假触发上反复调参。

**下一项、依赖与负责文件建议：**

1. **AEC 30 分钟验证**（无代码依赖，可立刻做）：外放播放已知语音 + 同进程 `getUserMedia({echoCancellation:true})` 采集，比较她说话时与静音时的采集电平差；残留需低于用户说话电平约 15dB。结果决定 VOICE-04 走 Chromium AEC、macOS `AVAudioEngine.voiceProcessingEnabled`，还是 GStreamer AEC3。
2. **VOICE-02**（P0，可与 VOICE-01 并行）：新增 `web/live2d/voice-capture.js`，改 `composer.js` 录入交互与 `main.js` 三个 IPC。这一步单独就能把首音从 10.3s 拉到约 6.8s，是性价比最高的一段。
3. **VOICE-03**（P0，依赖 02）：新增 `lib/stream-chat.js`，改 `llmOnce` 与播放队列，拉到 3s 级。
4. **VOICE-04**（P1，依赖 03 + AEC 结论）。
