## 完成内容

### 为什么是"加元素"而不是"改管线"

房间已经有 `RenderPass → UnrealBloomPass → 移轴 → ACES 调色（含动态颗粒与暗角）` 这条完整后处理链。再挂一个 composer 只会和它抢最终输出。真正缺的不是管线上的打磨，而是**画面里的体积感**：有空气的光、在室内能看见的天气、夜里活着的东西。

### 四个元素

| 元素 | 做法 | 挂在哪 |
|---|---|---|
| 窗光柱 | 从窗户矩形沿太阳方向挤出的楔形网格，自定义着色器做横向软边 + 纵向衰减 + 缓慢噪声 | `sun.position − sun.target`（跟着太阳走）|
| 浮尘 | 420 个点，漂移全在顶点着色器里算（零 CPU），只在光柱强度非零时可见 | 复用光柱强度 |
| 玻璃雨 | 窗内侧一张平面，着色器画水珠网格 + 下滑拖尾 + 薄雾 | `W.rain`（房间自己的平滑天气值）|
| 夜萤 | 46 个点，脉冲发光，只在夜里出现 | `world.altDeg` |

三条约束写在模块头注释里：只读房间状态、失败就什么都不做、元素必须落在画面内。

## 验证证据

**关键结论：这类改动是可以无头验证的。** 这纠正了我在 `AGENT-SCOPE.md` 里的判断。

真实房间页（`index.html`，含 bloom/移轴/调色全链路）能在 headless Chromium + SwiftShader 软件渲染下跑起来：需要 HTTP 服务（不能用 `file://`）、`--use-angle=swiftshader --enable-unsafe-swiftshader`、以及接受单帧渲染约 4 秒。房间自己的 `?at=`/`?wx=`/`?cam=` 三个查询参数正好提供了确定性。

| 命令 | 结果 | 能证明 / 不能证明 |
|---|---|---|
| `python3 tools/room-fx-probe.py` | **4/4 场景通过** | 能证明：模块不降级、无脚本错误、各元素在给定时刻/天气下真的在画面内且覆盖面积合理、雨只落在玻璃范围。不能证明：好看不好看、以及在你的默认镜头下量感是否合适 |
| dawn 07:20 clear | shaft=0.197，在画面内，像素差 2.50% vs 噪声 0.62%（4 倍信噪比） | 晨光低角度时最明显 |

| rain 14:10 rain | rain=1.000，面积 < 35%（确认没糊满屏） | 雨天玻璃上可见 |
| night 22:30 clear | fly=0.900，在画面内 | 夜萤只在窗外锥内生成，所以每一只都看得见 |
| `node --test --test-timeout=30000 test/` | 357 用例 346 PASS | 与本次改动无关（web 层不改 node 测试）；11 项仍为既有缺 fixture |

### 指标是怎么定的（踩过的坑）

1. 一开始直接逐像素比较开/关截图 → 每个场景都"变化 9%"，因为调色 pass 的**动态胶片颗粒**每帧每像素抖 ±0.02。
2. 改成块平均（16×16）消颗粒 → 噪声降到 2.5–3.5%，但窗外**海面本身在动**，把 ROI 圈进窗户反而更吵。
3. 最终判定用**几何投影覆盖率**：把网格顶点投影到屏幕算 NDC 包围盒，`area=0` 就等于"这个特效没画在画面里"。这个量没有噪声，也不靠阈值争论。像素差降级为参考信息打印出来。

第一次调的参数是错的：光柱强度 0.85、长度 6 单位，渲染出来是**整间房被加了一层暖雾**，不是光柱。降到 0.30、长度上限 4、横向衰减 2.2 次方之后才成为窗边的一层光。
