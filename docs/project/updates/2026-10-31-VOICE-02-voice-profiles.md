# VOICE-02 · 可选音色与歌曲分析

> 2026-10-31 · 承接 VOICE-01（翻唱升 K 与试听）

## 用户提出的三件事

1. 「薛之谦的就很低，女声就像老太太」
2. 「我实际是比较喜欢孙燕姿的音色，应该可以选择想要的音色」
3. 「最好是能分析出来歌曲，如果改成女声应该怎么调参数，节奏速度是不是都要调整」

这三句话其实是三个**独立**的层次，混在一起看永远调不好：

| 症状 | 真正的原因 | 解法 | 这次做了什么 |
|---|---|---|---|
| 像老太太 | **音色本身**偏暗偏沙 | 换参考音频 | 音色档案 + 切换 |
| 很低的段落唱不实 | **音域**不匹配 | 整首升 K | VOICE-01 已完成 |
| 换人唱要调什么 | 缺**量化依据** | 分析报告 | 新增分析脚本 |
| 节奏要不要动 | 时长对齐精度 | 修补偿误差 | 修了 370ms 漂移 |

**关键认知：升 K 只能改音高，改不了一个声音的年龄。**

之前用的 `ref-sing-magnetic.wav`，实测 `p50 = 163Hz` —— 比不少男歌手还低。
用它唱 115Hz 的男声原曲，就算升 6 个半音把音高搬对了，音色本身偏暗偏沙，
听感依然是老太太。这不是音域问题，是参考选错了。

## 一、音色档案（`lib/voice-profiles.js`）

音色和音域**必须分开存**，因为它们由不同的东西决定：

- **音色** = 参考音频 → 年龄感、明亮度、气息。换参考才变。
- **音域** = `range.lo / hi` → 整首升几个半音。换参考不会变。

```json
{ "id": "magnetic", "name": "磁性", "ref": "ref-magnetic.wav",
  "tone": "低音厚、略带沙，成熟感最强",
  "range": { "lo": 165, "hi": null } }
```

**合成音色不设上界，真人歌手有。** 这条不是随手定的：
合成音色的上限由 Seed-VC 的 f0 条件决定，跟着走就行；真人受生理限制，
超过就挤。所以 `hi` 只对真人档案有意义。

内置三档（magnetic / warm / cool-thick）都是现有素材，加一档 `sunyanzi`：

```json
{ "id": "sunyanzi", "name": "孙燕姿", "ref": "sunyanzi.wav",
  "range": { "lo": 164.8, "hi": 493.9 },
  "provenance": "E3–B4 来自声乐分析（巅峰质量音域），非官方测量" }
```

音域数据要**注明来源和不确定性**。网上流传孙燕姿是 D3–D5，另一处说是 C5–F5，
两者互相矛盾（下限比上限还高），没有任何可验证的测量。采信的是声乐分析口径
「巅峰质量音域 E3–B4」，并在档案里写明这是参考区间不是官方数据。

## 二、双向音域约束

`voice_range.py` 原来只有一条规则：把最低音抬到固定 165Hz。现在按音色算：

```
下界约束：min_shift = 12·log2(lo / p05)   低音必须能唱实
上界约束：max_shift = 12·log2(hi / p90)   高音不能挤
```

两个约束冲突时**往回退并明说**，而不是硬算一个数：

> 本要升 7 个半音才够，但最高音会顶到 494Hz 上限，只能升 1 个 ——
> 低音区会留一点虚，这是妥协。

还有一条更本质的判断：**歌比音色宽，整体移调救不回来**。

```
歌的跨度 = 12·log2(p90 / p05)
音色跨度 = 12·log2(hi / lo)
```

薛之谦这首跨度 18.2 个半音，孙燕姿 19.0 —— 能唱，但接近满负荷。
如果歌有 24.8 个半音，对 19.0 的音色就是硬冲突，报告里直接标 `conflict`。

**保留 `round` 而不是 `ceil`**：`12·log2(165/115.2)=6.2`，取 6 后低音落在
162.9Hz，比 165 差 2Hz（0.22 个半音）—— 听不出来，但伴奏少变薄一点。
差不到半个半音就值得省这一次变调。

## 三、歌曲分析（`scripts/analyze_song.py`）

一次算全，写进 `work/report.json`：音域分位数、BPM、调性、
**每个音色各该升多少**。切换音色不用重跑分析 —— 歌的属性没变，换的只是选哪一档。

实测《我好像在哪见过你》：

```
时长 279.15s   BPM 123.0   调性 A# 小调
人声音域 p05=115.2Hz p50=232.5Hz p90=329.1Hz  跨度 18.2 个半音

磁性       升 +6 半音 → E 小调
温暖       升 +7 半音 → F 小调
清冷厚实     升 +7 半音 → F 小调
孙燕姿      升 +6 半音 → E 小调
```

**调性做了交叉验证**：人声单独测 A# 小调（score 0.58），伴奏单独测也是
A# 小调（score 0.71）。两条独立路径一致，这个结论才敢往 UI 上放。
相关系数不是概率，只用来判断「像不像一个明确的调」，注释里写清楚了。

### 节奏和速度：不用调

这是**实测结论**，不是感觉：

- 变调用 `asetrate`（音高速度一起变）+ `atempo`（拉回速度），补偿后时长应与源相等
- 修复前 25 秒片段短 **44ms**，按比例整首 279 秒会短约 **370ms**
- 修完变调后伴奏精确 **25.000000s**，人声 24.996281s 被 `apad` 补齐

所以「升 K 顺便调速度」是个误会。SVC 是逐帧换音色，不改节拍。

唯一例外：BPM ≥ 132 且升幅 ≥ 5 时，咬字会被听成「赶」。这是编曲层面，
报告里提示可以降 2%，但**默认不做** —— 改节奏等于改歌。

## 四、修掉的两个真 bug

### 1. 时长漂移（会毁掉整首）

`amix` 不做长度对齐，以最长轨为准，短的那轨尾部直接消失。
变调后的伴奏短 370ms，结尾那段就变成人声干唱。

修法：变调后 `apad` + `-t` 硬截到源长度；混音时两轨都 `apad` 再统一截断。
以伴奏为基准是因为它承载节奏骨架。

### 2. 换音色失效（会让用户以为功能没做）

中间产物目录原来是 `preview-${SHIFT}`，**不含音色**。
换音色后如果升 K 数相同（都是 6），`her.wav` 已存在就被跳过 ——
用户点「换音色再听一版」，听到的还是旧音色。

修法：`preview-${VOICE_ID}-${SHIFT}` 和 `full-${VOICE_ID}-${SHIFT}`。
这条是自测时发现的，不在原计划里。

## 五、实测：换音色到底改了什么

同一段副歌（142.5s 起，25 秒），都升 6 个半音，只换参考：

| | p05 | p50 | p90 | 频谱重心 | 中频占比 | 空气感(>6k) |
|---|---|---|---|---|---|---|
| 磁性 | 187.3 | 337.0 | 392.2 | 2693Hz | 57.2% | 24.1% |
| 温暖 | 183.7 | 334.4 | 391.7 | 2434Hz | 62.2% | 20.9% |
| 原片段 | — | — | — | 2784Hz | 52.8% | 25.0% |

- **音高差 2.6Hz（0.8%）** → 换音色确实不改音域，两个变量是独立的
- **频谱重心差 258Hz（9.6%）** → 音色确实变了，但方向要看清

温暖档更「暖」= 中频多 5 个百分点、高频少 3 个百分点，整体更暗。
也就是说它更柔，但**不更亮**。想要「不沙且通透」，现有三档都做不到 ——
它们都是同一个 TTS 声音的不同 instruct 变体，本质是同一个人的不同 EQ。

升 6 半音后 `low<200Hz` 的能量从 4.6% 降到 0.97%，**低音区基本被清空了**。
所以「老太太」感里「低」的部分已经解决，剩下的是音色本身的「沙」。

## 六、孙燕姿这一步差什么

**还差一段她的干净人声**（≥10 秒，人声清晰、无伴奏）。

这不是技术限制，是素材：Seed-VC 靠参考音频的 speaker embedding 定音色，
不能凭空生成一个没听过的人。音域分析不需要音频，已经能算
（报告里孙燕姿那行就是真算出来的），但合成必须有。

放进去就能用，不需要改任何配置：

```
~/.smartcompanion/voices/sunyanzi.wav
```

`voice-profiles` 会扫用户目录，找到了就自动 `usable: true`。
UI 上那一档现在是「孙燕姿·待启用」，变淡但仍可点 —— 点了会返回具体放置路径。
不做成死按钮是因为「点不动」不会告诉用户缺什么。

## 没做的

- **没给 ffmpeg 编 rubberband**。当前 `asetrate+atempo` 会让共振峰一起上移，
  升 6 半音伴奏明显变薄（低频占比 47.5%→37.8%）。这是这条路线绕不开的，
  真要解决得换独立变调引擎。
- **没测孙燕姿的真实参考**，因为还没有素材。
- 三档 TTS 音色的 `lo`（165/175/170）是保守估计，不是实测出来的
  「在哪唱会虚」。要精确标定得做主观试听对比，机器测不出「虚」。
- 已入库的旧翻唱还是 shift=0 的产物，没有重新生成。
