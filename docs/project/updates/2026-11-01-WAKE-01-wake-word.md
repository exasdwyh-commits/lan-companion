# WAKE-01 语音唤醒与连续对话

2026-11-01 · 状态：代码完成，待真机验收

## 为什么做

用户原话：「目前不能持续对话，必须我要点麦克风，其实我只需要叫小艾同学这种，
它被提示词触发跟我对话就行。」

原来的语音只有一条路径：点麦克风 → 采一句 → 转写 → 回答。一次问答要两次点击
（一次开麦、一次下一轮），而且点的时候不能说话（点了才开始录），实际用起来像对讲机。

这次改的是**入口**：麦克风常开，听到名字才回应，之后每说一句答一句。

## 结构

```
待机（standby）                    对话（active）
  采一段 → 转写 → 判唤醒词            采一段 → 转写 → 直接答
      ↓ 命中                           ↓ 说完就答
    播「嗯？」→ 进入对话         静默 45s 或说「先这样」→ 回待机
```

两个循环都住在 `web/live2d/composer.js` 里，用的是原来那套
`voice-capture.js`（端点检测）+ `companion:transcribe`（转写）+ `ask()`（串行提问）。
没有新写一份采集 —— 那条链路已经被 VOICE-02/03/05 调稳了。

**唤醒判定是纯规则**（`lib/wake-word.js`），不调模型。理由是成本：待机时用户说的
每句话都要判一次，接模型等于把闲聊天变成按次计费。

## 三个非显然的决定

### 1. 繁体必须先转简体（否则一半的唤醒会随机失败）

实测 7 句合成音，whisper **3 句输出繁体**：

```
说「小艾同学，帮我看看这个报错」 → 听成「小艾同學,幫我看看這個抱錯」
说「深蓝，你在吗」               → 听成「深藍,你在嗎?」
```

唤醒词是按简体写的，于是这三句全部唤不醒。更麻烦的是它**不是稳定失败**：
同一句话有时简体有时繁体，用户会觉得「时好时坏」，比一直坏更难排查。

`normalize()` 里加了一张口语高频字的繁→简表（约 120 对）。加完之后 13/13。
切出来交给模型的那句话也走同一张表，否则气泡里一半繁体一半简体，不像她说的。

### 2. 只允许漏首字或尾字，不允许漏中间

「小艾同学」漏掉中间的「艾」就是「小同学」—— 这是个真实存在的日常词，
教室里随便一句「小同学」都会把她叫起来。首尾则安全得多：「艾同学」「小艾同」
不是正常词，出现就说明是转写吞了字。

配套一条：**两字词后面只跟一个字就结束时不命中**。
「小爱豆」「小爱情」都是「小艾」+ 一个孤字，正常叫名字只会是「小艾」或者
「小艾，帮我关灯」。这条把两字词最常见的误触发挡掉了。

### 3. 判端点的参数按状态分开

喊名字是短促的一声，喊完就停住等你应。用对话态的 450ms 尾静音 + 600ms 最短语音
来判，唤醒要平白多等 0.3 秒。所以待机用 `endSilenceMs: 320 / minUtteranceMs: 420`
（`WAKE.standbyEndpoint`），对话态保持原参数（怕切断长句）。

## 实测

### 真实链路（合成音 → whisper → 匹配）

`scripts/wake-word-check.js`，跳过麦克风，从音频文件走完整 STT：

| 模型 | 平均耗时 | 正例 7 句 | 负例 6 句 |
|---|---|---|---|
| small（现在用的） | 862ms | **7/7** | **6/6** |
| base | 243ms | 6/7 | 6/6 |

base 更快但它把「深蓝」听成「新蘭」——名字唤不醒是硬伤，**不用 base**。
（顺带确认：VOICE-05 记的「base 0.25s / 小模型不够准」在这里又验证了一次，
而且这次是败在她自己的名字上。）

### 唤醒延迟

```
喊完 → 端点判完 0.32s → 转写 0.86s → 匹配 → ack 合成 0.93s → 出声
                                            ≈ 2.1s
```

ack 之后还要等 1.3s 才开麦（无 AEC 时不能录到她自己的回应），所以喊完名字到
「能接着说下一句」约 3.4s。这段空白是当前最明显的体感问题，见「未解决」。

## 未解决 / 待验

1. **真麦克风一次没跑过**。端点阈值在真实环境（风扇、键盘、外放）里的表现未知。
2. **ack 的 1.3s 空档**：无 AEC 时不能更短，否则录到她自己的「嗯？」。有 AEC 时可以
   压到 1s（已按 `aecKnown` 分支），但 AEC 在真机上到底开没开还没读过。
3. **长回复时会话提前开麦**：等她说话用的是字数估算
   （`min(9000, 字数×210) + 1200`），她说超过约 40 字时，用户插话的位置可能
   还在她话里 —— 那一段会录到她自己。真正的解法是让舞台在播放结束时回报一次，
   比估算可靠得多。
4. **待机常开麦克风**：macOS 菜单栏的橙点会一直亮。菜单里能关
   （「语音唤醒 · 叫名字就能聊」），但关掉后只能手动点麦克风。
5. **别人说话会触发转写**：待机时非唤醒的句子也会跑一次本地 STT（0.9s、本机、
   不花钱），只为了判断「是不是在叫她」。CPU 占用随环境噪音变化。
