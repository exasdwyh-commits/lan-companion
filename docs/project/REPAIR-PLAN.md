## 结论

先保证现有剧情、奖励、素材能稳定交付，再加强陪伴反馈。点击台词、称呼推送、视频锚点和触摸尾部淡出已经实现，不重复开发。推荐顺序：**可靠性收尾 → 关系反馈 → 剧情节奏与回看 → 日常变化 → 声音/新场景**。

对照方依据用户提供的马尔福功能清单；本轮实际审阅的是我们的当前 Electron 源码，未重新独立验证马尔福实现。当前证据见 [FIX-01 交付](updates/2026-10-31-FIX-01-story-and-plan.md)。历史测试结果不替代这次复查。

## P0：现有功能可靠性

### R0 · 剧情交互卡住与幕次错位 — 本轮源码已修

- 根因：请求中渲染出的按钮保持 disabled，请求 finally 只清 busy；选择分支时前端额外 index++，后端仍停在分支幕。
- 修复：统一同步继续/选择/关闭的 busy 状态；choose 只解析当前幕，advance 才推进；识别后端 done 并显示“重看”。
- 验收：真实 renderer 脚本 + 真实适配器/状态机，临时数据覆盖 A/B 通关、重复奖励、分支后还有下一幕、失败重试、防连点。6/6 通过。
- **尚未重建 App，也未做原生窗口交互/视觉验收**。源码修复不等于当前运行包已更新。

## 执行方式与 BMAD 衔接

1. 在 TASKS 领取一个 R 项，声明文件范围；当前并行聊天较多，尤其 main/preload/world 不可多人同时写。一个小项完成后释放文件。
2. 新会话用 `bmad-help` 路由。小项用 `bmad-spec` 把本页对应 R 项及现状整理为 Why/Capabilities/Constraints/Non-goals/Success signal；再用 `bmad-build` 按 spec 实现与审查。涉及关系/历史状态迁移时单独记录设计和兼容策略。
3. BMAD 产物仍放 `docs/project/bmad/`。本页是本轮修复规划，不冒称已经执行未来工作流或通过未来验收。
4. 每项保留“复现失败 → 修复 → 回归”的证据；持久化用临时数据，UI 用 Ego 支持路径与原生实际操作。静态截图不能证明按钮全流程可点。
5. 完成后更新 STATUS、TASKS、updates、CHANGELOG。无需新素材的代码小项先验收，素材项单独过授权与视觉检查。
