## 推荐决策

以 B 的柔和体积、精致绘本质感制作统一角色母图；日常互动继续验证 Live2D，舞蹈先做短时、可重复、音频同步的专门动作。先验 180px 的脸、轮廓与动作，再投入完整 PSD 绑模。现有 Electron 舞台和 Director 复用，不能另开第三套产品。

3. 修正为实际 4×3 记录，选取下两排的 8 幅完整双腿角色，只修改取样坐标；PNG/原片不动。相应 `chibi-dance.js` 已重新派生。**这些帧仍多为同侧伸手，不能标记为完整左右交替的顺拐舞。**
4. 旧哼唱是合成音色，交付文档写明正弦/谐波/颤音；不是角色真实唱腔。仍保留原件与现有音频，未冒充人声优化已完成。

6. Live2D 旧报告称参数 null；本轮 Ego 实测 `loaded=true`，参数从 `{angleX:0,angleY:0,mouthOpenY:0,eyeLOpen:1}` 变为 `{angleX:6,angleY:-30,mouthOpenY:1,eyeLOpen:0.8}`。当前无需修参数探针，澜自己的 PSD/.moc3 仍缺，示例成功不证明澜已 Live2D 化。

## B 版具体美术修改

- 保留蓝长发、横向鳍耳、蓝白女仆裙、鲸鱼围裙、侧后鲸尾、两条人腿。
- 约两头身、宽圆脸、短躯干与短手短腿；先固定正/侧/背比例和脚底锚点。
- 保留 B 的柔和体积与材质层次，将碎发归为大束，银色裙边只留一个主纹样；180px 下优先眼眉嘴，避免蕾丝噪声。
- 平静默认微笑；委屈、俏皮、得意、害羞为可切换表情，不把委屈固定成默认脸。
- 母图需检查 140/180/220px；未经三视图与多动作校验，不能把一张好看的图当作一致身份资产包。

## 如何“学会”跳舞

1. 先逐拍标注参考：同侧手脚方向、肩/胯重心、脚底接触、头与胸朝向；参考脚部不足时补完整镜头。拟先做 8 拍、左右完整交替的小循环；具体 BPM、帧数等实测再定。
2. 用 B 身份画关键姿态；顺序检查“左侧→回中→右侧→回中”，禁止把普通交叉走路称作顺拐。真人姿态估计只能辅助，Q 版短腿、遮挡和尾巴需手工修正。
3. 发/裙/尾巴做延迟跟随，脚接触地面时禁止水平滑动；减少头部无意抖动。大转向优先专门动作片段，不用一张正面图硬扭。
4. 日常使用 Live2D 参数组合，舞蹈使用作者制作的 motion 或专门连续图集；不让随机待机、眨眼/摸头和舞蹈同时争夺同一组身体参数。
5. 由音频 `currentTime` 与 beat markers 驱动动作相位，循环取模；暂停/恢复/说话打断后重对齐。进入/退出使用淡入淡出，GL 丢失或缺素材退回已有待机。

## 如何“学会”哼唱

1. 先制作 6–10 秒短人声作为候选长度：原创/授权旋律的真人轻哼，或可控歌声模型生成的干声。确定旋律、节拍和音域后，再使用现有 `scripts/sing_cover_file.sh` / Seed-VC singing 路径转换到已选角色音色。
2. F0/音符来自源哼唱；音色转换本身不负责作曲。优先保留小音域、柔和起音与自然换气，分别试听闭口「嗯」和轻「啦」。
3. 从真实音频提取能量包络驱动嘴型，闭口哼唱保持较小开合；只用音量开嘴不等于音素级准确。动作节拍与嘴型共用同一音频时间线。
4. 先导入一个离线短成品，不每次互动即时训练/生成；复用 DW-05 主音频调度，聊天/阅读/歌曲打断时让位，不能另建不受控播放器。
5. 本轮未提取参考音轨、未测 BPM、未生产新哼唱或听感验收；Qwen3-TTS 官方定位为语音生成/克隆，没有本项目可依赖的精确旋律唱歌验收，因此不以“念啦啦啦”替代歌声。

## Live2D 实施要求

- 扩充既有 [分层规格](LIVE2D-POC.md)：左右上臂/前臂/手、左右大腿/小腿/鞋必须独立，单层整臂整腿不利于舞蹈；背发/侧发/刘海、尾根/尾身/尾鳍、上下裙摆也分别补绘遮挡部分。
- 正面母图 → 同坐标可补绘分层 PSD → Cubism Editor 网格/变形器/参数 → `.model3.json` / `.moc3` / 贴图 / physics / expressions / motions。单图生成不能跳过中间工序。
- 先验追视、自然眨眼、音频口型、头/尾触摸，再验左右踏步；同一舞台上检查 180px、透明命中/穿透、拖拽、模式切换与资源释放。
- 物理限幅防止发束穿脸/裙摆抖动；记录同机待机/舞蹈的 CPU、内存与帧时间后再判断常驻成本，目前没有性能数值。
- 发布时分别核对角色素材、模型和 SDK 条款。官方 SDK 说明区分个人/小规模及 Expandable Application，不能用“免费拟开源”直接推导任意模型加载器均豁免。
