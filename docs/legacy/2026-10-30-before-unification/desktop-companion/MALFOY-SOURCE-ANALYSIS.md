# 马尔福 Desktop 源码级拆解

> 依据：本地 `MALFOY-ENGINE/`（Electron 完整源码）+ `_testonly/malfoy/media/`（全套素材）
> 结论全部来自读代码和量测，不引用它的技术文档。

---

## 0. 先纠正一个前提：它不是"代码更完整"

| | 马尔福 | 我们的 PetDesk |
|---|---|---|
| 总行数 | 2139 | 2290 |
| 最大单文件 | `app.js` 623 行 | `PetController.swift` 635 行 |
| 内容数据 | `data.js` 137 行 | 无（散在代码里） |
| 特效代码 | 916 行（`magic.js` 511 + `fx.js` 405） | 0 |
| 打包体积 | 528 MB（含 30 个 4K 视频） | 16 MB |

**代码量几乎一样。** 它所谓的"完整"，不在工程实现，而在三件事：

1. **内容闭环** —— 一个好感度数字，串起场景 / 章节 / 相册 / 回忆 / 称呼五个系统
2. **不接模型也有完整体验** —— 断开网络，她照样看书、照样能走完第一章
3. **视觉完成度** —— 1300 行 WebGL（法阵、翡翠火、银色记忆漩涡、辉光）

而 `package.json` 里写着 `"description": "AI 女友桌面 · 马尔福小姐（即梦 AI 短剧工作室 Demo）"`。

**它是给工作室做的样片，不是产品。** 这解释了后面所有的硬编码——样片只需要在自己机器上跑一遍出片。

## 1. 内容资产清单（这才是真正值钱的部分）

| 类别 | 数量 | 明细 |
|---|---|---|
| 4K 视频 | **17 条** | 剧情 6（含 2 条分支）、动作 7（入场×2 / 待机×3 / 触摸 / 睡姿）、待机循环 4 |
| 静帧 | **11 张** | 场景锚点 2、空场景 1、睡姿 1、选择背景 1、相册 6 |
| 音频 | 1 段 | `bgm.mp3`（钢琴，音量压到 0.35 垫底） |
| 带时间码双语字幕 | 11 条 | 覆盖 28.7 秒，中文字合计 113 字 |

**第一章实测总时长：65 秒**（15.1×4 + 分支 5.1）。就这么多。

这句话很重要：**65 秒剧情 + 6 张相框 + 5 个动作片段，就足够撑起"这是个完整产品"的观感。** 不需要一小时内容，不需要配音剧集。

所有动作片段带 AAC 立体声（演员配音），待机循环是**静音**的（所以能配独立 BGM）。

## 2. 四层架构，边界干净得可怕

```
data.js (137 行)      角色 + 场景 + 章节 + 字幕 + 相册 + 数值   ← 换角色只改这里
   ↓
app.js (623 行)       状态机 / 播放调度 / 解锁 / 面板渲染       ← 一行业务数据都没有
   ↓
main.js (184 行)      窗口形态 / 菜单栏 / LLM 代理 / TTS        ← 渲染进程拿不到密钥
   ↓
index.html + css      DOM 层（4 个 video + 1 个 img 叠成舞台）
```

它的自我定位写在注释里：**"换角色/换人设只改这里，引擎不动"**、**"每个定制款 = 一份 persona + 一套 media/ + 一套 clips，其余复用引擎"**。

——这就是他做定制生意的底子。我们现在的台词和动作映射还写在 Swift 里，换一套内容要重新编译。

## 3. 六个真正值得抄的设计（都有代码依据）

### 3.1 字幕挂在视频时间码上，不是 TTS

```js
"1-1": { src: "media/1-1.mp4", caps: [[8.2, 11.95, "入学第三天，就敢闯禁书区。", "Third day here..."]] }
```

台词是**预先写死的秒级区间**，靠 `requestAnimationFrame` 每帧比对 `currentTime` 来显示。所以：

- 表演节奏可控（她知道第 8.2 秒才开口）
- **不花一分钱 TTS**，也不会有 AI 语音的塑料感
- 自由聊天才走 edge-tts 合成

这是"内容型角色"和"聊天机器人"的分界线。我们目前只有系统 `say` 朗读回复，没有"演出"这一层。

### 3.2 `empty` 空场景图 + 入场片段 = "她走进来坐下"

```js
empty: "media/empty-sofa.jpg",   // 场景里没有她的样子
enter: "media/D1.mp4",
```

进场景时先显示**空沙发**，再播入场片段，播完切锚点图。观众看到的是"她把书放下、坐下来"，而不是"视频突然开始循环"。成本只是一张空场景图（找模型把人物抹掉即可）。

### 3.3 用数组重复来编码概率权重

```js
ambient: ["a.mp4", "a.mp4", "b.mp4"],  // 注释：D8 偶尔翻书，出现概率 2/3
```

不写权重字段，直接重复元素。改概率只需多写一个字。这种"数据格式迁就人眼"的习惯，整份 data.js 都是。

### 3.4 睡姿不循环，定格在静帧

```js
sleep: "media/D5.mp4",
sleepEndAt: 5.0,
sleepStill: "media/sleep-sofa.jpg",
```

睡姿片段只播前 5 秒就冻结成静帧。原因很实在：**呼吸循环一旦被看出来，就假得刺眼**；而睡着的画面本来就该几乎不动。这个我们完全没有——我们的 `sleep-01.mp4` 是整段循环的。

### 3.5 12 秒不选，就等于选 A

```js
const timer = setTimeout(() => pick("A"), 12000); // 沉默也是一种回答
```

不是超时判负，是**把沉默当成一种性格化选择**。低成本，高情绪。

### 3.6 一个数字驱动五个系统

`aff`（0–100）一套阈值，同时控制：场景解锁（20）、相册解锁（10/20/35/50/65/80）、章节解锁（40）、称呼变化（0/20/40）、章末奖励（+10）。加一点好感度，五个地方同时有反馈。

## 4. 五个不能抄的（同样是代码证据）

### 4.1 硬编码到离开作者机器就跑不了

```js
const proxy = "http://127.0.0.1:10808";                         // 写死的本地代理
const TTS_BIN = "~/Documents/VScode/selfmedia/venv-tts/bin/edge-tts"; // 指向另一个项目
const ENV_FILE = "~/.hermes/.env";                              // 从别的项目读密钥
const LLM_URL = "https://apihub.agnes-ai.com/v1/chat/completions"; // 单一服务商
```

样片可以这么写，产品不行。我们的 `Settings` 已经支持任意 OpenAI 兼容端点 + Bearer，这一项我们领先。

### 4.2 零错误态

`playDesk()` 里没有 `onerror`。视频加载失败 = 黑屏，界面上没有任何提示，用户只会以为软件坏了。素材路径写错一个字母，整个场景静默死掉。

我们的 `Stage.swift` 有静帧兜底、`status == .failed` 会往气泡里报错。

### 4.3 存档在 localStorage

```js
localStorage.setItem("malfoy-desktop-v1", JSON.stringify(S));
```

清一下浏览器数据 = 删档。换机不迁移。更麻烦的是它的双窗口（壁纸 + 互动）靠 `storage` 事件同步状态——这是浏览器才有的机制，一旦换成原生或桌面壳就得重做。我们用 `Application Support/history-pet.json`，方向是对的。

### 4.4 好感度可刷

```js
if (r.voice || r.text) addAff(1);   // 每发一句话 +1，无冷却、无上限
```

连发 100 句"嗯"就能从 0 刷到满，六张相册全解锁。触摸有 45 秒冷却，聊天却没有任何限制——设计上是个漏洞。

### 4.5 没有任何自动化验证

没有测试、没有自检开关、没有 CI。它的正确性靠"作者手动点一遍"。我们有 `--selftest`，dump 图层透明度 / 播放速率 / 气泡文字，这条已经反超。

## 5. 我们的真实差距（具体到文件）

| 能力 | 他们 | 我们 | 差距实质 |
|---|---|---|---|
| 多场景 | `scenes` 字典 + 入场片段 + 每场景独立 hit 区域 | 单素材包 | 数据层缺失 |
| 剧情 | `flow` DSL（clip / then:choice / branch）+ 时间码字幕 | 无 | 内容与引擎都缺 |
| 相册 | 6 张 + 阈值解锁 + 拍立得日期戳 | 无 | 纯内容，最容易补 |
| 回忆（冥想盆） | 复用已看过的 clip 做索引 | 无 | 引擎 10 行，内容是复用 |
| 衣橱 | 换场景 = 换装扮 | 无 | 依赖多场景 |
| 称呼变化 | `callNames` 阈值 | 无 | 3 行代码 |
| 好感度 | 单整数 + 五处阈值 | 无 | 缺一个持久化数字 |
| 待机循环接缝 | **0.6 秒交叉淡化兜住** | `AVPlayerLooper` 硬切 | **真实缺陷**（见下） |
| 座位/入场 | 空场景图过渡 | 直接淡入 | 观感差异 |
| 菜单栏 | Tray + 开机自启 + 重入场 | 无 statusItem | 需补 |
| 分发形态 | Web 一套 → Electron + **Wallpaper Engine** | 只有 .app | 商业上最值钱的一条 |

### 最该马上修的一条：待机循环的接缝

他们用**两个 video 元素交替**，每段播到 `duration - 0.6s` 就在另一个元素上启动下一段并交叉淡化：

```js
if (v.currentTime >= v.duration - XF) { ... 切换 ... }   // XF = 0.6
```

我们是 `AVPlayerLooper` 单元素循环，**首尾帧不严格一致就会看见一次跳帧**。他们的做法是"不管素材接不接得上，我都用 0.6 秒淡化把它糊过去"——更鲁棒。这个改动在 `Stage.swift`，工作量不大。

## 6. 被低估的一招：同一份 Web 内容，两个市场

```js
window.wallpaperPropertyListener = { applyUserProperties(p) { ... } };
```

这是 **Wallpaper Engine** 的 Web 壁纸 API。配合 `main.js` 里的 `type: "desktop"`，同一份 `web/` 目录：

- **Windows**：上传 Steam 创意工坊，当成动态壁纸卖（Wallpaper Engine 用户基数极大，且是付费生态）
- **macOS**：Electron 壳跑成桌面程序

内容做一次，渠道铺两个。这对"精品模板"这个模式几乎是量身定做的分发结构——而且 Wallpaper Engine 那边**没有签名公证问题**，省掉 macOS 分发最痛的一环。

## 7. 对"定制桌宠"产品的三个结论

**1. 一套模板的真实单位不是"代码"，是这些：**

```
17 条视频（6 剧情 + 7 动作 + 4 待机循环）
11 张静帧（5 场景 + 6 相册）
1 段 BGM
1 份 137 行的 data.js（persona + 场景 + 字幕 + 阈值）
```

生成成本按我们之前算的积分价，一套 ¥30–60；**贵的是分镜设计和把那 11 条字幕的秒数对上**。这跟我之前说的"贵的是踩提示词"一致，但现在有了确切的量化边界。

**2. 65 秒剧情就够。** 别按"短剧"的思路做时长，按"一次完整体验"的思路做密度。

**3. 双形态分发是它最聪明的地方，也是最容易被我忽略的地方。** 我们一直在纠结 macOS 签名公证，而它压根没打算只走 macOS。

## 8. 建议的落地顺序

| 步骤 | 内容 | 为什么排这里 |
|---|---|---|
| **1**（半天） | 把 PetDesk 的内容抽成 `pack.json`：scenes / clips / captions / unlockAt / callNames。Swift 只做解释器 | 不做这步，后面每加一个模板都要改代码 |
| **2**（半天） | 修 `Stage.swift` 的待机循环：改成双 player 交替 + 0.6s 交叉淡化 | 唯一影响"现在就能看"的缺陷 |
| **3**（一天） | 加两个最小面板：**相册** + **剧情**。用现有 6 段素材就能演 | 面板是"产品感"的主要来源，且不依赖新素材 |
| **4**（决策） | 要不要做 Web 版复用到 Wallpaper Engine | 这是商业结构问题，不是技术问题，值得单独判断 |

## 附：它的 bug 清单（读代码时顺手记的）

- `checkUnlocks(why)` 声明了 `why` 参数但从没用过
- `addAff` 在聊天里无冷却无上限（见 4.4）
- `enterScene` 里 `S.scene` 存的是字符串 id，但 `scene()` 读的是闭包变量 `sceneId`；两窗口同步时 `load()` 只改 `S`，不重算 `sceneId` → 切场景后另一个窗口显示不一致
- `amb` 是个手写的假元素（`{ pause, play, classList }`），只为让 `closePlayer` 能统一调用，属于补丁痕迹
- `runChapter` 结束后 `showCard("第一章　完")` 里的章号是写死的字符串，加第二章要改代码
- `sleepEndAt` 只有 sofa 场景有，armchair 没睡姿（`sleep: null`），逻辑上安全但配置不完整
