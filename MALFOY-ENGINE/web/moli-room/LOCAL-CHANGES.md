### 改动时踩过的坑（留给下一个人）

- **海面不能做成圆盘**。半径 46 的圆盘与半径 7.4 的沙岛同心、只差 0.05 高度，大平面深度精度不够 → 海面从沙地里透出来，满屏等距白条。海必须用 `RingGeometry`（内径小于沙岛半径）。
- **GLSL 里的模板插值要确认真的插进去了**。写成 `$(` 而不是 `${` 时 shader 编译失败但页面不报错，只是效果没出来。
- 上游 `ground.material` 带雪覆盖 shader，在这个太阳下会烧成白色，所以沙地另建材质。
- 上游 22 个远景山丘是**环形城墙**（立在草地边缘一圈），草地换成海面后会变成一圈挡视野的绿刺；本轮选择隐藏它们并自建低矮海岛。
- **GLTFLoader 解析完 `matrixWorld` 是单位矩阵**，不先 `gltf.scene.updateMatrixWorld(true)` 就把节点旋转烘进几何，顶点还是躺着——骨骼分区全部落错部位的根因。
- **GLB 里有约 2000 个坐标垃圾顶点**（未初始化值 1e30 量级），蒙皮分区前必须过滤（`Number.isFinite` + 范围检查），否则包围盒和 IK 全被带偏。
- 上游 `command(act)` 只改 `life.cmd`，正在执行的 step 队列不会立刻中断。自动化验证动作用 `?act=<name>` 会被 `snapTo` 瞬间传送、跳过走路与 settle，测不出真实流程；要复现真实体验就调 `MOLI_DEBUG.update(1/60)` 循环快进虚拟时间。
- **改了 `lan-model.js` 却没效果，先怀疑浏览器磁盘缓存。** `skinning` 第一次改成 `true` 后实测仍是 `false`，`reload()` 也不管用；必须 `page.cdp("Network.setCacheDisabled", {cacheDisabled:true})` + URL 加 `?nocache=`，同时把 `index.html` 里的 `lan-model.js?v=` 也 bump。否则会在无辜代码上反复找 bug。
- **蒙皮"验状态"是不够的**：`life.pk`、`rig.rotation.x`、`skeleton.boneMatrices` 全部正确时，画面仍可能一动不动。必须截图看。

## 当前边界

这是浏览器场景预览，尚未接 Electron 世界窗口、聊天、记忆或语音仲裁。WORLD-MODEL-11 将真实混元 3.1 多视图模型 `assets/lan-room/lan-v2-game.glb` 接入默认入口，原版茉莉的整套可视 rig 隐藏，角色组与场景命中保留；新增「看澜」近看按钮，加载状态与失败提示。

角色按上游日程自主行动（睡眠/起床运动/游戏/看电视/读书/吃饭/听歌），能走、能跳上床、能坐、能躺、能持物；姿态由 `lan-model.js` 回放到新模型骨骼上。原版墨水体 rig 仍保留但默认隐藏，模型加载失败时自动退回它。

地面接触（WORLD-RIG-15）：上游根骨高度公式按 0.78 细身标定，Q 版整条腿只有 0.1115 米，坐姿直接下沉 0.148 米会把脚压到地板下。`pose()` 里增加三道约束——臀部落地下限（`HIP_SEATED`）、脚目标不得低于地面、坐姿按 `seated` 权重强制踩地（行走踏步不受影响），最后以「腿够不到就抬身体」兜底。躺姿另修两处几何偏差：bind 姿势脚比髋靠前 3 cm（转 −90° 后变「上」），以及 IK 膝弯项方向指向上方，导致腿翘 11.8°；改为去前倾 + 全长伸展后归零。调试用 `?bones=1` 显示骨骼小球，`lanModel.dbg` 导出 `{rootYm, soleL, soleR, legDyL, legDzL, lying}`；注意 `sole` 是相对她自身地板平面（`moli.position.y`）的高度，躺姿下无物理意义。

躺姿睡眠（WORLD-RIG-16）：整套躺姿常数也是按 0.78 细身定的，套在这具 1.30 米长的 Q 版上全部不成立。① 沿床面滑 `LYING_SLIDE=.42`——原锚点让她头顶到 z=−2.03，床头板在 −2.02，头穿出床外；② 躺姿 `rootYm` 由 `0.105` 改 `0.06` 落到**实测床垫顶面 0.46**（`PL.lie.p.y=0.64` 是原墨水体自己的地板平面，不是床面，这一点上一轮判错了）；③ 裙骨躺姿旋转由 `+1.26` 改 `−1.15`——正向会把裙摆轴转到世界 (0,+0.95,−0.31) 即朝上 72°，等于把自己架在裙撑上，也是裙底的来源；④ 双腿收向中线并压低（髋距 0.176 而腿长 0.146，沿轴伸直会张开 31°、脚悬空 0.25 米），`hint` 改膝朝床面；⑤ 双臂按模型自身「肩→腕」向量折到身侧，不再沿用站立偏移穿出被子；⑥ `syncBlanketProxy` 的覆盖盒改成**楔形**（头端 z×0.16、x×0.74，脚端 z×0.55，中段 0.92×0.56），并把 `mesh.geometry` 换掉、用 `userData.lanQuiltShape` 防重复——平板盒子会把被子顶成筐，把头一起扣住。实测头顶回到 −1.36、髋离床垫 0.03 米、床尾低角度看不到裙底，站/坐鞋底仍为 0。

躺姿再下沉（WORLD-RIG-17）：用户接受过渡帧穿模，要求躺定后再低一点。① **床垫顶面重测为 0.53**——对整张床做射线网格扫描（x −2.1~−0.6 步 0.15、z −2.0~0.2 步 0.2），大片稳定在 0.52~0.53，上一轮记的 0.46 只在靠墙的床架边出现。躯干底面原在 0.66，仍悬空 0.13 米，躺姿 `rootYm` 由 `0.06` 改 `−0.07`。② 被子覆盖盒原来只有 8 个角点，楔形 taper 后峰值厚度仅 `0.56×0.55=0.31` 米，小于躯干 0.33 米——这是「人在被子上」而非「人在被子里」的几何原因，抬高被子没用，必须加厚。改 `BoxGeometry(1,1,1,1,8,1)` 沿长轴细分，厚度按插值曲线 `[[−.5,.70],[−.25,.95],[0,1],[.25,.86],[.5,.06]]` 给（头顶几乎压平、胸口最厚、脚端收窄）；`scale` 改 `1.14×len×0.48`（加宽因为裙摆铺开后超过肩宽），盒子中心沿世界 Y 抬 0.05（骨骼走身体中轴，布料要护住她的背），`len` 由 `dist+0.42` 收到 `dist−0.12` 让头端停在肩膀。③ 裙骨躺姿转角实测定表：0→0.866、−0.28→0.893、−0.5→0.897、−1.1→0.826、−1.4→0.791（世界 y 最高点），**改为零旋转**——站立时裙摆沿局部 −Y 下垂，身体绕 X 转 −90° 后正好映射到世界 +Z，本来就沿床面朝脚摊开、盖住大腿；任何额外扭转都会把裙撑立起来（−1.15 是垂直戳进床垫，只剩腰上一圈、大腿反露；−0.28 在胯部顶到 0.893 比被面高，戳出一个白尖）。实测躯干底面 0.66→0.451（压进床垫 0.08）、被子峰值 0.949→0.904、裙摆最高点 0.893→0.866（被面之下），头露在被子边界之外，站/坐鞋底仍为 0。注意：`blanket` 的抬升由 `measureBlanket` 一次性射线计算、只在小屋首次躺下且模型已 rigged 时触发（`blanketLan` 门），改高度后不重算被子，必须重载页面才看得到真实效果。

裙子走光（WORLD-RIG-18）：用户反馈「穿裙子在床上就走光了」。**根因不是姿态，是裙片只有单面**——面朝外的正面正常渲染，反面被 `FrontSide` 剔除，于是从裙摆下方看进去时**视线穿过裙壁直接落到皮肤上**。躺下（`pitch=−π/2`）裙锥开口正对床尾、坐下（`read_bed`）开口朝前下方，两个姿势都是直视；她又是短裙光腿、裙内没有任何几何能挡，所以看起来就是"裙底全露"。RIG-16/17 两轮都以外部轮廓为准（"床尾看不出裙底"），漏掉了"绕视角看进去"。修法两件，都挂 `lan-skirt` 骨，**不动 GLB、不动权重、不动外形轮廓**：① `buildSkirtLining()` 把同一份几何里"三个顶点全由裙骨主导"的 **36,277 面**抠出来另存一份 `BufferGeometry`（共享 position/normal/uv/skinIndex/skinWeight），用 `MeshStandardMaterial({ color: 0x1b2747, side: BackSide, skinning: true })` 画成**裙内衬**——共享 skin 属性所以变形与裙片逐顶点一致，只画反面所以永远在裙片之后、外轮廓零变化，只取裙骨分组所以不会把身体别处绕序反的面画成暗块；② 裙骨下挂 **`lan-bloomers`**：`0.128×0.100×0.112` 米椭球，中心在裙骨原点下方 `0.072` 米（绝对高度约 0.163，正好在髋 0.175 之下）。裙锥口本身是开的，只有内衬挡不住正对锥轴的视线，这件**安全裤**负责填住；半径远小于该高度裙片半径（≥0.22 米）所以物理上戳不出裙外，平时完全不可见。尺寸是按裙片**分层最大半径**实测（1 cm 一档，y 0.056~0.263、最大 0.346 含花边）定的，不要凭感觉改大。`info.costume` 导出 `{liningFaces, bloomers}` 供验收。判定方法值得复用：**按骨骼主导权重把面分组染纯色**（腿红 15,181 面／臂绿 15,009 面／裙蓝 36,277 面），正对裙口拍一张——画面里没有红色就说明看不到腿；再用"内衬染品红 + 身体染青"排除残留粉色是花边而非皮肤。取景时**目标点要对准裙骨世界坐标**，对准 rig 中心会把裙摆挤出倾斜对焦的清晰带，拍出来一片糊。

裙内打码（WORLD-RIG-19）：用户「你改成模糊马赛克就行」。RIG-18 的遮挡逻辑**原样保留**（36,277 面内衬 + 团块尺寸/挂点/父子关系全部不动，**几何顶点一个没改**），只把外观换成马赛克。① `skirtMosaicTexture()` 生成 128×128 `CanvasTexture`，画 8×8 个 16px 方块，色值在深蓝灰里随机（`#2b323d`…`#8e9ab0`），`magFilter = NearestFilter` 保证硬边；尺寸取 2 的幂才让 WebGL1 下 `repeat + mipmap` 合法，远处自动糊成一片，正好是"模糊马赛克"。**块数按实测定的**：内衬 UV 铺满 `0.0004–0.9996`（见 `benchmarks/2026-11-01-WORLD-RIG-19/measure-uv.mjs`），裙口宽约 0.52 米，8 块≈6 cm/块，屏幕上明显是方块而非噪点。② 内衬材质加 `emissiveMap` 同贴图（`emissive:#4a5468 × .5`）——**裙内朝向床面收不到任何主光，纯 `map` 会被压成一片全黑**，格子的影都没有。③ 安全裤换成**低多边形球 `SphereGeometry(1,12,9)` + 正交投影 UV + `MeshBasicMaterial({map: mosaic})`**：球面 UV 绕极点收束会把方格拉成条纹，所以把每个顶点的 UV 重写成 `x/y*0.5+0.5` 的平面投影；材质不受光是刻意的——打码块本来就不该被灯照，否则阴影里必然变黑。**两个坑**：`emissive` 是**均匀加项**，会把 `flatShading` 的逐面明暗一起抬平，几何棱角全部消失（只剩一个光滑深色球），块感只能来自各面自身颜色/照度差，不能靠加自发光提亮；另外**整件衣服和身体是同一个 `SkinnedMesh`**（`lan-smooth-skin`，靠 UV 区域区分），所以"给身体染纯色"这类测试无法区分皮肤与布料，判断遮挡仍然只能靠**按主导骨分组染色**。判定结果：腿染纯红后，`read_bed` 三机位的红色像素占比 0.02%/0.08%/0.08%，**全部落在裙外膝盖，裙口内零红色**；站姿正面裙外侧无任何补丁、外形零变化。`info.costume` 多导一个 `mosaic: true`。

已知边界：开合跳双手举高时，大振袖会展开成翼状——Q 版大袖 + 虚拟骨的固有结果，要根治得在 Blender 做平滑权重后重导出；Q 版头径约等于躯干厚度（头 0.864、躯干厚 0.33），被子一旦盖住躯干就必然与头顶齐平，现在靠「被子头端在 z −1.18 处收低 + 头在该边界之外」露头，不是靠被子更低；长发软物偶有一两个小白点穿出被面；裙摆背面插入床垫约 0.34 米（俯视与床尾都被被子挡住，贴床沿侧看才可能发现）；上床/起身过渡帧仍有穿模，用户已明示接受；裙内衬让 36k 面多走一次骨骼蒙皮 pass（真机帧率未见异常，但没做逐帧耗时对比），安全裤（RIG-19 起是一块不受光的打码团块）是刚体挂裙骨、腿大幅弯曲时位置会偏一点（它只负责挡视线，不需要跟腿）。

运行副本来自 `assets/lan-3d-model-design-v2/model-trial-v1/lan-b-multiview-game-preview.glb`，哈希与来源见 `assets/lan-room/lan-model.source.json`。原始模型保留；未改 App 入口或包。

## 运行

从 `desktop-companion` 根目录执行：

```bash
python3 -m http.server 8947 --bind 127.0.0.1
```

打开 `http://127.0.0.1:8947/MALFOY-ENGINE/web/moli-room/`。也可继续用旧 `world-prototype/` 路径，会跳到这里。

可复现预览：`?lang=zh&lat=31.2&lon=121.5&city=preview&wx=clear&at=15:30`；此参数固定位置/天气/时间用于画面验证，不代表真实天气服务实测。默认页面保留原版天气定位行为。点击电视、方向键选卡带、Enter 开始/暂停、Backspace 返回卡带、Esc 回房间。

取景辅助参数（仅用于截图验证）：`?cam=px,py,pz,tx,ty,tz` 定相机、`?at=HH:MM` 定时间、`?wx=` 定天气。取远景时需同时放开 `OrbitControls` 的方位角与距离限制。
